# 13 - Agency Managed Email Infrastructure

**Purpose:** Define the architecture and business model for providing White-Labeled, Self-Hosted Email Services to clients using a Coolify VPS. This setup replaces 3rd-party services (like Cloudflare Routing or Google Workspace) with a 100% independent, highly profitable agency-owned infrastructure.

## 1. The Technology Stack
* **The Engine (Backend):** [Mailcow](https://mailcow.email/) — a complete Docker-based mail server wrapping Postfix (SMTP, 1998), Dovecot (IMAP, 2002), Rspamd (antispam), ClamAV (antivirus), and SOGo (webmail/calendar/contacts).
* **The Panel (Frontend):** **SOGo** — built into Mailcow. Provides webmail, calendar, and contacts at `mail.clientdomain.com`. No separate container needed.
* **The Host:** Coolify VPS (Contabo, 12 GB RAM).

## 2. The Client Experience
* **White-Label Access:** Clients visit `mail.clientdomain.com` and see a clean SOGo webmail login screen branded with their domain.
* **Unlimited Team Mailboxes:** Because the agency owns the server, a single client can have infinite mailboxes (`ceo@domain.com`, `sales@domain.com`, `support@domain.com`) at zero additional cost.
* **Calendar & Contacts:** SOGo includes CalDAV/CardDAV — clients get calendar and contact sync alongside webmail, competing directly with Google Workspace ($6/user/month).

## 3. Strict DNS Requirements (Crucial for Independence)
To ensure emails sent from the VPS do not land in Gmail/Yahoo spam folders, the following DNS records **must** be configured for every client domain:
1. **rDNS (Reverse DNS):** The VPS IP address must resolve back to the mail server's hostname at the VPS provider level (e.g., Contabo).
2. **SPF (Sender Policy Framework):** Authorizes the VPS IP to send emails on behalf of the client domain.
3. **DKIM (DomainKeys Identified Mail):** A cryptographic signature generated by Mailcow's Rspamd to verify the email was not tampered with.
4. **DMARC:** Instructs receiving servers to reject unauthorized emails spoofing the client's domain.

*(Note: Mailcow's admin UI has a built-in DKIM key generator. Add a domain, click ARC → Keys, and publish the displayed TXT record.)*

## 4. Application Architecture (How the API sends emails)
To ensure seamless code extraction via the Blueprint Model, the NestJS codebase handles emails using an **Event-Driven Modular Architecture**:
* **The Transport (Core):** The `core` pack contains a `communications` module that reads `SMTP_HOST` from `.env` and exposes a generic `sendEmail()` function via nodemailer. It knows nothing about domain logic.
* **The Templates (Sector Modules):** The HTML templates and business logic live strictly inside their respective sectors (e.g., `apps/api/src/modules/apparel/templates/`).
* **The Extraction Benefit:** When a client only buys the Books sector, they receive the Core transport and the Books templates. The Apparel templates are deleted automatically with the Apparel folder, leaving zero dead code.

## 5. The Ultimate Agency Flex (Future API Integration)
Mailcow provides a comprehensive REST API for managing users and domains.
In the future, the agency's `managed-services` API module can integrate with Mailcow's API. This will allow clients to log into their bespoke E-Commerce Admin Panel, click "Create New Employee Email", and automatically provision a new inbox on the Mailcow server without any manual agency intervention.
